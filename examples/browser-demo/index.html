Hakka Web demo

The inspector overlay is the floating button in the bottom-right corner. This page loads a handful of illustrative sample requests so the Network list isn't empty on first paint, then lets you fire real traffic from the buttons below and watch it land in the overlay live. Full walkthrough in README.md (open it as a file: GitHub renders it, or just read the source).

Drop into any page with <script src="hakka-browser.global.js"></script> then Hakka.start().

Network: real fetch / XHR

Same-origin requests, captured by the real interceptor and enriched with real DNS/TLS/ connect/TTFB from the browser's Performance Timeline (resourceTiming: true below). Open a captured row's Timing tab. On localhost, dns/connect/tls often round to 0 since there's no real lookup or handshake to measure; ttfb and download still show real numbers.

Resource Timing scope: img / script tags

hakka-browser only intercepts fetch/XMLHttpRequest/ WebSocket. A plain <img>/<script> load isn't request-shaped, so it never becomes a Network row (see the initiatorType filter in src/capture/resourceTiming.ts). This button loads both for real. Check your browser's own devtools Network tab to see them; you won't see anything new appear in Hakka's panel, which is the correct, documented behavior, not a bug.

sendBeacon capture

captureBeacons: true patches navigator.sendBeacon. This fires a real beacon (fire-and-forget, no response body expected) and it lands in the Network list tagged sendBeacon.

WebSocket

This demo has no WebSocket server, so the connection itself fails. The interceptor still records the attempt the moment new WebSocket() is called, so it shows up with a Frames tab regardless. Point hakka-browser at a real ws:/// wss:// endpoint in your own app to see live frames.

Worker store: getLogs / getBody

The capture store (dedup, retention, filter/search, HAR/OTel serialization) runs off the main thread in a Web Worker; only the interceptors stay main-thread. slimEcho (default on) keeps full bodies out of every snapshot; getBody is a separate round trip to the Worker for the real bytes, on demand.

Rules: Mock

Hakka.mockEngine.addRule(...) registers a rule on load; the button below fetches the matching path and never touches the network. The response is served entirely from the rule.

Rules: Throttle

Toggles Hakka.ThrottleEngine between the Slow 3G preset and off. Once active it delays every subsequent request on this page (fetch, XHR, WebSocket). Try the fetch button above again after switching it on.

Rules: Breakpoints

Registers a request breakpoint on /breakpoint-demo. The fetch below pauses before it's sent. The overlay auto-opens on the Rules → Breakpoints panel so you can edit or resume/abort it from there. The pending fetch() promise stays unsettled until you do.

Trace propagation

trace: true is on below, so same-origin requests carry a real x-hakka-trace header. Open a captured row's Request Headers tab to see it. Pair with hakka-node on your API server to group the client hop with the server work it triggers under one Trace.
