<Aside type="tip" title="What you'll have">
  By the end of this page, your React Native app captures network requests and shows them in the Hakka inspector —
  trigger a call, shake the device or long-press the bubble, and see it. No proxy, no certificate, no cloud account.
</Aside>

`hakka-react-native` is the app-facing package for React Native. It provides a TypeScript API, a TurboModule bridge to the native Hakka SDKs and optional monitors. The inspector is rendered by the native iOS and Android SDKs.

<Badge text="Beta" variant="caution" /> Fully working and on npm. It has less production soak time than the web and
Next.js SDKs.

## What Hakka captures

| Traffic type                      | Captured | Notes                                                      |
| --------------------------------- | -------- | ---------------------------------------------------------- |
| `fetch`                           | Auto     | Through the configured native networking integration       |
| `XHR`                             | Auto     | Through the configured native networking integration       |
| WebSocket frames                  | No       | No JavaScript frame interceptor in native mode             |
| Native HTTP (URLSession / OkHttp) | Auto     | Via TurboModule and the native SDK                         |
| Native WebSocket metadata         | Opt-in   | Message count + close code only; payloads require JS layer |
| GraphQL operation name            | Auto     | Parsed from request body                                   |

## Setup

The native inspector needs no clipboard package or React Native UI peers. It uses
the platform clipboard directly.

<Steps>

1.  **Install the package**

          <Tabs syncKey="pkg-manager">

    <TabItem label="npm">

    ```bash title="Terminal"
    npm install hakka-react-native
    ```

          </TabItem>

    <TabItem label="pnpm">

    ```bash title="Terminal"
    pnpm add hakka-react-native
    ```

          </TabItem>

    <TabItem label="yarn">

    ```bash title="Terminal"
    yarn add hakka-react-native
    ```

          </TabItem>

    <TabItem label="bun">

    ```bash title="Terminal"
    bun add hakka-react-native
    ```

          </TabItem>

    </Tabs>

    Then run native install:

    ```bash title="Terminal"
    cd ios && pod install
    ```

2.  **Start capture**

    Call `Hakka.start` once, before any network traffic — top of your entry file works well.

    ```ts title="index.ts"
    import { Hakka } from 'hakka-react-native'

    Hakka.start({
      maxRequests: 500,
      maxBodySize: 256 * 1024,
    })
    ```

    Native capture is the only mode and the default. See [Native Capture](/react-native/capture-modes/) for setup requirements and coverage.

3.  **Open the native inspector**

    Start native capture, then open a surface from a debug menu, deep link, or another app action:

    ```ts title="debug-menu.ts"
    Hakka.start()
    const didOpen = await Hakka.show({ as: 'bubble' })
    // 'bubble' | 'sheet' | 'fullscreen'; Hakka.hide() dismisses it.
    ```

    `Hakka.show()` resolves to `true` after native presentation and `false` when the native module
    or native UI artifact is unavailable. Native UI requires native capture; it is
    unavailable while capture is stopped.

4.  **Verify it works**

    Trigger any network call in your app (an API fetch, an image load, anything). Then open the native
    inspector with the bubble or shake gesture. The request should appear with method, URL, status,
    and timing.

</Steps>

## `Hakka.start` options

| Option        | Type       | Default    | Description                                                       |
| ------------- | ---------- | ---------- | ----------------------------------------------------------------- |
| `mode`        | `'native'` | `'native'` | Native-only capture; omit this option.                            |
| `maxRequests` | `number`   | `500`      | Maximum requests kept in the in-memory store. Oldest are evicted. |
| `maxBodySize` | `number`   | `262144`   | Maximum body size to capture per request/response, in bytes.      |

## Native inspector

The native surfaces provide the platform inspector, including the bubble, sheet, and fullscreen
presentations. iOS's canonical UI is included in the React Native pod automatically; Android apps
add `hakka-network` and `hakka-performance` as needed, plus `hakka-ui` for the inspector.

The package no longer exports `hakka-react-native/ui` or ships a React Native inspector, theme, or
renderer plugin surface.
Native controls can vary by platform. Session APIs, hooks, capture, clipboard shake-to-share,
WebView support, storage and query monitors, and Rozenite remain available programmatically when a
native surface does not expose a matching control.

## Prebuilt iOS SDK

Release npm packages include `HakkaNative.xcframework` with iOS device and simulator slices.
CocoaPods links the precompiled native capture engine and inspector; the React Native bridge
remains source so it builds against your app's React Native version. No separate download is
needed during `pod install`.

To edit the native SDK in a local checkout, install pods in source mode:

```bash
HAKKA_IOS_USE_SOURCE=1 pod install
```

A checkout without the XCFramework also uses source automatically. Run `pod install` again
when changing modes. The binary supports iOS 16 and later, arm64 devices, and arm64/x86_64
simulators. The declared visionOS target continues to compile from source.

## Optional monitors

```tsx title="Monitors.tsx"
import { useQueryMonitor } from 'hakka-react-native/monitors'

function Monitors() {
  useQueryMonitor([['users']], queryClient)
  return null
}
```

Monitors are add-ons — they annotate captured requests with React Query cache state. Not required for the base capture pipeline.

## New Architecture

The package requires its TurboModule/codegen bridge. Startup throws when it is missing; rebuild the native app after installation. There is no JavaScript fallback.
