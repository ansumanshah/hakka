<Aside type="caution" title="Expo Go is not supported">
  Hakka includes native code. Expo Go cannot load it — use a development build (`npx expo run:ios` / `npx expo
  run:android`).
</Aside>

<Aside type="tip" title="What you'll have">
  By the end of this page, your Expo app captures network requests and shows them in the Hakka inspector. No proxy, no
  certificate, no cloud account.
</Aside>

## Install

<Tabs syncKey="pkg-manager">
  <TabItem label="npm">```bash npm install hakka-react-native ```</TabItem>
  <TabItem label="pnpm">```bash pnpm add hakka-react-native ```</TabItem>
  <TabItem label="yarn">```bash yarn add hakka-react-native ```</TabItem>
  <TabItem label="bun">```bash bun add hakka-react-native ```</TabItem>
</Tabs>

Then install the Expo development client:

```bash title="Terminal"
npx expo install expo-dev-client
```

The native inspector uses the platform clipboard directly. No clipboard package or
React Native UI peer is required.

## Setup

<Steps>

1. **Add the plugin to `app.json`**

   ```json title="app.json"
   {
     "expo": {
       "plugins": [["hakka-react-native", { "uiDelivery": "bundled" }]]
     }
   }
   ```

   Use `uiDelivery: "bundled"` for local development and installs outside Google
   Play. This includes the inspector in the app, so `expo run:android` can open it.
   For Play-distributed builds, set `uiDelivery: "play"` (the plugin default) to
   generate an app-owned `:hakkaInspector` on-demand module. Capture stays in the
   base app and `Hakka.show()` downloads the inspector when needed. Verify that
   path through [Internal App Sharing](/android/on-demand-ui/#verification). Set `uiDelivery: "disabled"` or
   `androidUI: false` to omit it. iOS includes the canonical native UI in the
   React Native pod through autolinking and CocoaPods.

2. **Opt in to Android performance collectors** _(optional)_

   ```json title="app.json"
   {
     "expo": {
       "plugins": [["hakka-react-native", { "uiDelivery": "bundled", "androidPerformance": true }]]
     }
   }
   ```

   Performance collectors stay opt-in so the base native capture setup stays small.

3. **Rebuild native projects**

   ```bash title="Terminal"
   npx expo prebuild --clean
   npx expo run:ios
   npx expo run:android
   ```

4. **Verify it works**

   Start capture in your app entry point before requests run:

   ```ts
   import { Hakka } from 'hakka-react-native'

   if (__DEV__) Hakka.start()
   ```

   From an app button or your own debug menu, call
   `await Hakka.show({ as: 'sheet' })` and check that it returns `true`.
   Make a network request and confirm it appears with method, status, and timing.
   Hakka does not add an item to Expo's development menu automatically.

</Steps>

## Day-to-Day Development

After your development build is installed, JS-only changes do not require a rebuild:

```bash title="Terminal"
npx expo start
```

You only need to rebuild (`npx expo run:ios` / `npx expo run:android`) when you change native dependencies or plugin configuration.

## Native inspector

The native inspector is opened from the app through `Hakka.show({ as: 'bubble' | 'sheet' | 'fullscreen' })`
after starting native capture. It returns a promise resolving to `true` after native
presentation, or `false` when native UI is unavailable. `Hakka.hide()` dismisses it. The removed
`hakka-react-native/ui` entry point and its React Native UI peers are not part of Expo setup.

## SDK 56 Note

Expo SDK 56's Apple native-module improvements do not change Hakka's current integration path. Hakka remains a standalone React Native package with a TurboModule/codegen bridge over native Android and Swift SDKs.
