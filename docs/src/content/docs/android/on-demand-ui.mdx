---
title: On-demand Android inspector
description: Ship capture in the base app and download the native inspector for internal users.
---

For an internal production build, keep `hakka-network` and optionally
`hakka-performance` in the base app. Put `hakka-ui` in an app-owned
[on-demand dynamic feature](https://developer.android.com/guide/playcore/feature-delivery/on-demand).
The inspector then adds no UI code or resources to the initial install. Google
Play downloads the feature before the app opens the inspector. This is the
default production path generated by the Expo plugin: `Hakka.show()` starts
installation when the feature is absent and resolves only after the installed
inspector is presented. The bare React Native example includes this exact
feature layout.

A dynamic feature depends on its base application, so Hakka cannot publish one
universal feature module. Each consuming app owns the small delivery module and
places the published `hakka-ui` library inside it.

## Base application

Register the feature in the application module and keep capture in the base:

```groovy
android {
    dynamicFeatures = [":hakkaInspector"]

    buildTypes {
        release {
            minifyEnabled true
            shrinkResources true
        }
    }
}

dependencies {
    implementation("com.noodleapps.hakka:hakka-network:0.0.1")
    implementation("com.noodleapps.hakka:hakka-performance:0.0.1")
    implementation("com.google.android.play:feature-delivery:2.1.0")
    constraints {
        // Align modules already supplied by the RN base with the Compose feature.
        implementation("androidx.activity:activity:1.12.1")
        implementation("androidx.collection:collection:1.5.0")
        implementation("androidx.compose.runtime:runtime-annotation:1.10.0")
        implementation("androidx.core:core-ktx:1.17.0")
        implementation("androidx.emoji2:emoji2:1.4.0")
        implementation("androidx.emoji2:emoji2-views-helper:1.4.0")
        implementation("androidx.lifecycle:lifecycle-runtime:2.9.4")
        implementation("androidx.savedstate:savedstate:1.3.2")
    }
}
```

Set the base app metadata to the feature name. The example uses
`hakkaInspector`; set a different value only when your Gradle feature has a
different final path element.

```xml
<application>
    <meta-data
        android:name="com.noodleapps.hakka.INSPECTOR_MODULE"
        android:value="hakkaInspector" />
</application>
```

Call `Hakka.show()` only after your app's existing authorization check. Hakka
coalesces concurrent requests for the same feature, waits for
`SplitInstallSessionStatus.INSTALLED`, then attaches the base capture store and
presents the inspector. It resolves `false` for a rejected, cancelled, or failed
install, or when no current activity remains. Install SplitCompat in the base
application before React Native loads:

```kotlin
class MainApplication : Application() {
    override fun attachBaseContext(base: Context) {
        super.attachBaseContext(base)
        SplitCompat.install(this)
    }
}
```

## Feature module

Create `hakkaInspector/build.gradle`:

```groovy
plugins {
    id "com.android.dynamic-feature"
    id "org.jetbrains.kotlin.android"
}

android {
    namespace "com.example.app.hakkainspector"
    compileSdk rootProject.ext.compileSdkVersion

    defaultConfig {
        minSdk rootProject.ext.minSdkVersion
    }

    packaging {
        resources.excludes += "META-INF/androidx.*.version"
    }
}

dependencies {
    implementation project(":app")
    implementation("com.noodleapps.hakka:hakka-ui:0.0.1")
}
```

Configure its manifest for on-demand delivery:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:dist="http://schemas.android.com/apk/distribution"
    xmlns:tools="http://schemas.android.com/tools">
    <dist:module
        dist:instant="false"
        dist:title="@string/hakka_inspector_title">
        <dist:delivery>
            <dist:on-demand />
        </dist:delivery>
        <dist:fusing dist:include="false" />
    </dist:module>
    <application android:hasCode="true">
        <activity
            android:name="com.noodleapps.hakka.ui.HakkaActivity"
            android:theme="@android:style/Theme.DeviceDefault.Light.NoActionBar"
            tools:replace="android:theme" />
        <activity
            android:name="com.noodleapps.hakka.ui.DetailActivity"
            android:theme="@android:style/Theme.DeviceDefault.Light.NoActionBar"
            tools:replace="android:theme" />
        <activity
            android:name="com.noodleapps.hakka.ui.SettingsActivity"
            android:theme="@android:style/Theme.DeviceDefault.Light.NoActionBar"
            tools:replace="android:theme" />
        <provider android:name="androidx.core.content.FileProvider">
            <meta-data
                android:name="android.support.FILE_PROVIDER_PATHS"
                android:resource="@xml/hakka_inspector_file_paths"
                tools:replace="android:resource" />
        </provider>
    </application>
</manifest>
```

Define `hakka_inspector_title` in the base application's resources. Publish an
Android App Bundle; ordinary APK installation does not exercise Play Feature
Delivery. The base app also needs `res/xml/hakka_inspector_file_paths.xml` for
the merged FileProvider manifest; copy the small file from the runnable React
Native example. Keep the `HakkaUI` reflection rules from the example feature's
`proguard-rules.pro` when release minification is enabled.

## Bundled opt-out

Debug builds may keep `hakka-ui` as a normal dependency for fast local work. A
production build that intentionally bundles the inspector can do the same, but
it gives up the initial-install size benefit. Do not add both the normal UI
dependency and the dynamic feature to one variant.

## Verification

Use Internal App Sharing for the final test. For local testing, build a bundle
and let `bundletool` emulate module installation:

```bash
./gradlew :app:bundleRelease
bundletool build-apks \
  --bundle app/build/outputs/bundle/release/app-release.aab \
  --output /tmp/app.apks \
  --local-testing
bundletool install-apks --apks /tmp/app.apks
```

With bundletool 1.18.3 and Play Feature Delivery 2.1.0, the tested Android 17
emulator can load an emulated feature's code on the first download while leaving
its resource package unavailable until the process restarts. Test the immediate
download path through Internal App Sharing. To test the inspector UI itself on
that emulator, install the feature up front with
`bundletool install-apks --apks /tmp/app.apks --modules=base,hakkaInspector`.

Verify both paths:

1. The base app captures traffic before the inspector module is installed.
2. The app handles an unavailable inspector before installation.
3. The module downloads for an authorized internal account.
4. `await Hakka.show()` stays pending during download and resolves `true` only
   after bubble, sheet, or fullscreen presentation reads the existing capture store.
5. The base split contains no `com.noodleapps.hakka.ui` classes or Hakka UI resources.
